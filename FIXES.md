# Production Hardening — Fixes Applied

All 13 audited flaws addressed. 46 tests pass (incl. tests that exercise the
former failure paths).

| # | Severity | Flaw | Fix |
|---|----------|------|-----|
| 1 | Critical | Batch failure corrupted the session & lost committed work | Each assessment's DB writes run in a `begin_nested()` SAVEPOINT; batch items are isolated. Proven: 3 good + 1 bad item → 3 persisted. |
| 2 | Critical | DEMO connector (fabricates passes) shipped in prod | Gated by `demo_enabled()`; auto-off when `APP_ENV=production`, override via `ENABLE_DEMO_CONNECTOR`. |
| 3 | Critical | Any key could read/write any tenant | API keys are tenant-scoped (`key:tenantA,tenantB`); `authorize_tenant()` enforces 403 on mismatch. |
| 4 | High | Cached OAuth tokens never refreshed | Azure/CrowdStrike fetch lazily and refresh 60s before expiry. |
| 5 | High | CORS `*` + credentials (invalid/insecure) | Credentials only enabled when explicit origins are set; methods/headers narrowed. |
| 6 | High | `/findings` unbounded | `limit` (≤500) + `offset`, capped server-side. |
| 7 | High | Idempotency not atomic | PK on idempotency key + `IntegrityError` catch returns the race winner. |
| 8 | Medium | 500s leaked internal exception text | Generic 500 message; full detail logged only. |
| 9 | Medium | `create_all` on startup, no migrations | Alembic scaffolding + autogenerated initial migration; auto-create off in prod. |
| 10 | Medium | `tenacity` unused | `app/retry.py` retry policy applied to S3 writes (and available to connectors). |
| 11 | Medium | SQLite default in prod, no pool tuning | Prod+SQLite refused at startup; pool_size/max_overflow for PostgreSQL. |
| 12 | Medium | Telemetry duplicated unencrypted in findings table | Dropped the `telemetry` column; full telemetry lives only in the evidence store, referenced by id + hash. |
| 13 | Medium | Local evidence writes not concurrency-safe | Exclusive `flock` + `fsync` per append; S3 path retried. |

## Optimization round

Measured with a query counter on a 200-finding / 30-waiver tenant.

| Area | Before | After | Change |
|------|--------|-------|--------|
| `compliance_summary` | 51 queries, 35.4ms | **2 queries, 4.0ms** | Batched all active waivers into one query + an O(1) `WaiverIndex` (killed the N+1); column-only select instead of full ORM hydration. ~9× faster. |
| `drift` | full-ORM scan, list per key | **1 query, 1.1ms** | Column-only select + rolling last-two per key. |
| `/connectors` | N external health calls per request | cached | 60s TTL health cache in the registry. |

| hot-path imports | re-imported per call | module-level | Hoisted `frameworks` / `waivers` imports out of `compliance_summary`. |

A regression test (`test_summary_is_not_n_plus_one`) asserts the summary stays ≤6 queries.

## Architecture round ("a better way")

| Improvement | What changed |
|-------------|--------------|
| **Posture current-state table (CQRS-lite)** | `findings` stays the append-only audit log; a `posture` table holds one upserted row per (tenant, control, source, asset). `/summary` and `/drift` now read posture — **2 and 1 queries regardless of history size** (tested at 300 findings), instead of scanning the whole log. The finding write-path is centralized in `_commit_finding`, which upserts posture atomically in the same savepoint. |
| **OPA / Rego policy seam** | `POLICY_ENGINE=opa` + `OPA_URL` delegates control evaluation to an Open Policy Agent server (status from OPA, severity from the catalog); default stays the in-process rule engine. Sample `policies/compliance.rego` included. |
| **External-scanner ingestion** | `/ingest/securityhub` (AWS Security Hub via boto3) and `/ingest/report` (Prowler / Steampipe / Powerpipe JSON) normalize external results into findings via the shared `_commit_finding` path. Idempotent on external id (re-ingest → skipped). |
| **OSCAL export** | `/reports/oscal` emits a NIST OSCAL `assessment-results` document so auditors/GRC tools can ingest results directly. |

Centralizing the write path means live assessments and ingested findings share the same idempotency, evidence, posture, and notification logic. 81 tests pass.

- **No structural dup bugs remain**: scanned for duplicate class definitions, duplicate routes, and dangling references to removed symbols (`posture_key`/`SEP`/`previous_status`) — all clean after the integration fixes.
- **Posture invariants proven**: (1) one posture row per (tenant,control,source,asset) with latest status + prev_status, while the findings log keeps full history; (2) 12 concurrent same-key requests → 1 posture row + 1 finding (savepoint rolls back posture on the idempotency race — no orphan); (3) posture-derived summary matches a manual recount.
- **Closed a real gap**: Security Hub ingestion (`from_security_hub`, boto3) had **zero tests** — added a mocked test verifying ASFF→finding mapping (FAILED→fail, PASSED→pass), source tagging, and idempotent re-ingest.
- **Production-shape boot verified**: schema built via Alembic only (auto-create off), app serves assessments, posture summary, ingestion, OSCAL, and legacy sources over HTTP.
- **OSCAL shape checked**: valid `assessment-results` envelope with uuid/metadata/results and OSCAL-standard observations/findings.

## Optimize + innovate round

**Recheck:** scanned for duplicate classes/routes and dangling symbols (clean); re-verified posture invariants; full suite green.

**Optimization:** finding write-path 11 → 10 queries — the evidence-metadata row is now held by reference and its URI set in-session after the store write, instead of re-fetching it with an extra `get`. (The big read-path wins — posture-backed summary/drift, indexes, health cache — were the previous round; the write path is otherwise irreducible.)

**Innovations (all tested):**

| Feature | What it does |
|---------|--------------|
| **Risk-weighted scoring** | `/summary` now returns `risk_weighted_score` and `risk_exposure` alongside the raw pass-ratio — failures are weighted by severity (critical=10 … low=1), so a critical fail hurts the score more than a low one. Free (uses posture's severity column, no extra query). |
| **Remediation priority queue** | `/remediation` ranks open unwaived failures by impact = severity × asset criticality (from inventory), and projects the score if the top-N are fixed ("fix these and you go from 33% → 100%"). |
| **Tamper-evident evidence** | Each evidence record gets a `record_hash` over its immutable fields. `/evidence/verify` recomputes it (detects metadata edits) AND cross-checks the DB's telemetry hash against the hash actually persisted in the store (detects artifact edits). Proven: editing a stored hash is caught and the exact record flagged. |

87 tests pass.

## AI-governance + verifiable evidence + agentic policy + forecasting round

Built the four research-grounded directions. All integrate through the existing
posture / connector / crosswalk / evidence architecture. 97 tests pass.

| Feature | What it does | Endpoints |
|---------|--------------|-----------|
| **AI-governance control domain** | Assess an org's *own* AI systems on the data plane against ISO 42001 / NIST AI RMF / EU AI Act. 8 AI controls (inventory, risk/impact, data governance, human oversight, transparency, eval/bias, logging, robustness) mapped across all three frameworks. The `AIGOV` connector reads registered AI systems (tenant-scoped) and the policy engine evaluates them like any other control. | `POST/GET /ai-systems`, then normal `/assessments` with `source_system=AIGOV` |
| **Merkle transparency log** | Batches evidence record hashes into a Merkle tree and stores signed roots — gives auditors an inclusion proof per evidence item and detects any tampering, *without* per-write serialization (solves the hash-chain concurrency problem flagged earlier). | `POST /evidence/anchor`, `GET /evidence/anchors`, `GET /evidence/proof` |
| **NL → policy agent (human-in-the-loop)** | Describe a control in plain English; a deterministic compiler drafts a rule/Rego stub. Drafts are created **pending** and never active until a human approves — grounded in the research that final sign-off must rest with a person. | `POST /policy/draft`, `POST /policy/{id}/approve`, `GET /policy/drafts` |
| **Predictive drift forecast** | Least-squares regression over compliance snapshots projects the score forward and flags currently-failing controls as at-risk — reactive → proactive. | `GET /forecast` |

EU AI Act enforcement begins Aug 2, 2026, which makes the AI-governance domain
the timeliest addition; it reuses the crosswalk machinery so one AIGOV
assessment satisfies ISO 42001, NIST AI RMF, and EU AI Act references at once.

### Caveats
- The NL→policy compiler is a deterministic keyword/template stand-in for a full
  LLM agent — the seam exists to plug in a real model + OPA, and human approval
  is mandatory before any draft is active.
- The Merkle log proves *inclusion + integrity* of recorded evidence; it is not a
  zero-knowledge proof (the ZKMLOps direction remains a research frontier).
